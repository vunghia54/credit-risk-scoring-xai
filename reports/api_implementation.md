# FastAPI Inference Service

## Scope

This is an internal portfolio risk-scoring model and is not a production lending decision system. The service loads the frozen local pipeline and returns its uncalibrated class-1 predicted probability. It does not train, tune, calibrate, search thresholds, compute SHAP or make lending decisions.

Implementation responsibilities:

- `api/schemas.py`: strict request validation and public response contracts.
- `api/model_service.py`: trusted artifact integrity checks, one-row DataFrame construction and inference.
- `api/main.py`: application factory, lifespan loading, endpoints and sanitized HTTP errors.
- `tests/test_api.py`: TestClient integration and unit checks, using toy requests only.

## Frozen Model Artifact

The complete fitted sklearn Pipeline is loaded from `models/final_model.joblib`, with trusted metadata from `reports/final_model_artifact_metadata.json`.

- Model: XGBoost Baseline / XGB-01.
- Calibration: none.
- Default audit threshold: 0.50.
- Development operating threshold: 0.19.
- Artifact workflow: STEP18-v1.
- Artifact size: 66,547 bytes.
- SHA-256: `e99eb083596beac8b6b53c8ac75d90b028dce7bf9229d759a2967709d9084590`.

The artifact remains local and Git-ignored. It was fitted on TRAIN only in STEP 18 and is not regenerated by this API. Each application lifespan loads once; each worker process has its own instance. No request reloads or mutates the pipeline. Importing `api.main` constructs the application without loading the model.

## Artifact Integrity Verification

Startup requires both artifact and metadata. It validates the frozen identity, calibration, thresholds and schemas, reads artifact bytes, verifies SHA-256 against metadata and verifies byte length. The same verified bytes are passed to `joblib.load` through an in-memory stream, avoiding a second file read between verification and loading.

After loading, checks require a complete sklearn Pipeline with exactly `preprocessor` and `model`; the former must contain the existing DataQualityTransformer and TrainMedianImputer, and the latter must be a fitted XGBClassifier. Raw input names, 13 transformed names, class order `[0, 1]` and recorded model parameters must match. There is no scaler or calibration layer. Failure prevents application startup; no metadata or hash is silently rewritten.

Expected SHA-256 is read from trusted metadata, not duplicated as an API source constant. Metadata and model files must both come from trusted sources: replacing both could defeat a checksum-only integrity check.

## Input Contract

`POST /predict` accepts one JSON object with exactly these ten required keys. Nullable keys must still be supplied explicitly.

| Feature | Accepted input |
|---|---|
| RevolvingUtilizationOfUnsecuredLines | Finite number >= 0 |
| age | Integer >= 0 |
| NumberOfTime30-59DaysPastDueNotWorse | Integer >= 0 |
| DebtRatio | Finite number >= 0 |
| MonthlyIncome | Finite number >= 0 or null |
| NumberOfOpenCreditLinesAndLoans | Integer >= 0 |
| NumberOfTimes90DaysLate | Integer >= 0 |
| NumberRealEstateLoansOrLines | Integer >= 0 |
| NumberOfTime60-89DaysPastDueNotWorse | Integer >= 0 |
| NumberOfDependents | Integer >= 0 or null |

Extra keys are forbidden, including target, source index, group IDs and engineered indicators. Hyphenated delinquency names are the public JSON keys. Numeric strings and booleans are rejected. Integer fields require integer JSON values, not fractional values or `45.0`. There are no business upper caps; values must have a finite numeric representation. No income currency is assumed.

Validated input becomes a one-row numeric DataFrame in the canonical ten-feature order. Null becomes NaN for the frozen pipeline; no imputation, special-value correction or feature engineering occurs in the API layer. The pipeline itself supplies its three engineered indicators.

## Missing-Value Semantics

- `MonthlyIncome: null` represents missing income; frozen TRAIN-median imputation and the missing indicator apply.
- `MonthlyIncome: 0` remains zero, with the missing indicator off.
- `NumberOfDependents: null` is accepted and passed as missing.
- `age: 0` is accepted; the frozen preprocessor applies its existing zero-to-missing rule.
- Delinquency values 96/98 are accepted unchanged by request validation. The existing frozen pipeline handles them. Their source meaning remains unknown; they are not confirmed error or fraud codes.

## Endpoints

| Method/path | Behavior |
|---|---|
| GET /health | Returns `{"status":"ok","model_loaded":true}` only when a model service is available. |
| GET /model-info | Returns model identity, calibration, 10 raw feature names, feature counts, frozen thresholds, artifact digest/workflow and scope disclaimer. |
| POST /predict | Calls the already-loaded pipeline's `predict_proba` and returns class-1 probability with two inclusive threshold flags. |

Public responses exclude local absolute paths, raw training data, test records and private artifact provenance. A service without an initialized lifespan returns 503 rather than claiming health.

Measured TestClient response:

```json
{
  "model_name": "XGBoost Baseline / XGB-01",
  "predicted_probability": 0.02612978406250477,
```

This is frozen model output, not regulatory PD, production-validated PD or a guaranteed delinquency probability. No approve/reject or loan-decision field is returned.

## Threshold Semantics

Both flags mean `score >= threshold`, despite the shorter `above_` field names. Equality at 0.19 or 0.50 returns true for its corresponding flag; the nearest representable value below each threshold returns false. Thresholds come from frozen artifact metadata and are never optimized in the API. Neither flag is an instruction to approve or decline lending.

## Error Handling

Client schema errors return HTTP 422 with FastAPI-style `detail` entries containing type, location and message. Input values and validation context are omitted, preventing payload echo and allowing NaN/Infinity errors to be serialized as valid JSON. Missing fields, extras, negative numbers, wrong types and nonfinite inputs never reach prediction.

Missing artifact or metadata, hash mismatch, or incompatible loaded structure fails startup. A missing-artifact error directs developers to `python -m src.serialize_model`; the API never invokes it automatically. Unexpected prediction errors return HTTP 500 with `{"detail":"Model inference failed."}`. No stack trace or local path is returned, and no fabricated probability is substituted.

## Security Considerations

Joblib/pickle artifacts must only be loaded from trusted sources: deserialization may execute arbitrary code. SHA-256 is checked, but it is not a signature or proof of trust. Library compatibility and custom preprocessing source remain prerequisites for loading the artifact.

This local service currently has no authentication, rate limiting or production security controls. Do not expose it to the internet as a production service without adding appropriate controls. Startup fails closed on integrity problems.

Applicant payloads are not logged by default. Prediction errors log only the exception class, not its message or stack trace. There is no request database, file persistence or prediction history; requests are stateless. Deployment-level request logging must also avoid sensitive payload collection.

## Running Locally

Use the existing project virtual environment from the project root. The trusted artifact and matching metadata must already exist locally; the current verified artifact should not be regenerated for normal API use.

```powershell
.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

If the artifact is absent in a fresh checkout, review and explicitly run the existing approved local serialization workflow before starting the service. Model loading requires the project source, including custom preprocessing classes, to remain importable.

Installed direct API dependencies: FastAPI 0.142.2, Uvicorn 0.54.0, Pydantic 2.13.5 and HTTPX 0.28.1. `pip check` passed. Existing direct dependency pins are unchanged.

## Test Strategy

API tests use FastAPI TestClient with context managers so lifespan startup runs. They use the approved trusted local artifact and invented valid/invalid JSON inputs; they never load raw CSVs, validation labels or internal test observations. Tests require the local ignored artifact to be present, as a fresh checkout does not include it.

Seventy API tests passed, covering endpoints/OpenAPI, exactly ten required fields, forbidden extras, one load per lifespan, hash-before-unpickle behavior, missing files, metadata/model drift, null/zero semantics, age zero and 96/98, nonfinite JSON, strict numeric types, threshold equality and sanitized model failures. Direct independently loaded artifact predictions and API responses are exactly equal on eight parametrized toy cases. A separate seven-request smoke check also measured maximum and mean probability differences of zero.

The installed Starlette TestClient emits a deprecation warning for its HTTPX adapter. All API tests pass with the explicitly approved HTTPX dependency; no additional adapter or dependency was installed to suppress that warning.

Full-suite verification with `.\.venv\Scripts\python.exe -m pytest -v`: **410 passed, 4 warnings in 120.91 seconds**. This includes all 340 existing tests and 70 API tests. The warnings are three existing SHAP plotting deprecations and the Starlette/HTTPX TestClient deprecation described above.

## Limitations

Input validity does not imply that an observation is within the training distribution. Extreme finite inputs are not clipped by arbitrary business caps; underlying numeric/model failures still return sanitized server errors. No latency, load, external-validation, fairness or production-readiness claim is made. The artifact and all frozen decisions remain unchanged.

The internal test set was consumed in STEP 15 and is not used for API development, parity checks, examples or model decisions. Existing test and SHAP reports are not regenerated.

## What This API Is Not

This is not a lending approval system, production underwriting engine, regulatory credit-decision system or deployed public scoring service. No new model selection, retraining, calibration, threshold analysis or SHAP functionality is included.
